# Turn feedback into research standards

The feedback listed under "Files for this run" is a critique of earlier research. Your job is to turn it into general rules that future research on any company should follow, and add them to the research standards note in the knowledge notebook.

Read knowledge/research-standards.md first. Add a rule only if it is new or meaningfully strengthens an existing one, and use the action correct if the feedback shows an existing rule is wrong.

A good rule is general. It applies to future companies, not just the one critiqued, it is phrased as an instruction, and it says why in a few words. Leave out deal-specific numbers unless they illustrate the rule.

Write one line of JSON per rule, with these keys.

| Key | What to put in it |
|---|---|
| note | research-standards |
| action | add, or correct if it corrects an existing rule |
| lesson | The rule in one or two plain sentences |
| source | Who gave the feedback and on which research, if the file says |
| confidence | high, medium or low |

List at most 15 rules, the most important first. If nothing new is worth adding, write no lines. Do not use em dashes.

Put the JSON lines, and nothing else, between the output markers.
